# 备份、历史查询与报告固定 V24

## 数据保护

报告、查询及账号账本采用临时文件写入、fsync和原子替换，保留上一份可解析文件在数据目录的`.last-good/`。
发现损坏文件时拒绝继续覆盖，不再将读取失败当成空列表。
取消报告/查询写入时的1000/3000条静默截断；已被旧版截断且没有其他副本的数据不能由此次升级恢复。

服务启动及每6小时在服务器本机备份三份数据文件，保留最近30份完成的备份。
默认目录为数据目录同级的`<数据目录名>-backups`，可用BACKUP_DIR指定；目录私有，文件权限600。
每份备份有SHA256及结构校验，备份失败会记录错误，不覆盖原数据。
这些是同机备份，无法抵御整台服务器或磁盘丢失；异地副本仍需另行配置。

维护命令应使用与PM2服务一致的数据路径环境：

```bash
node storage-admin.js backup
node storage-admin.js list
node storage-admin.js verify /absolute/backup-folder
node storage-admin.js restore /absolute/backup-folder
```

restore默认仅验证。真正恢复须先停服务，确认备份后加`--apply`，再启动服务。
恢复前保存当前原始文件以备回退；恢复过程失败尝试回滚。恢复后的登录会话全部撤销，管理员和学生需重新登录，密码保留。
持续磁盘故障时回滚也可能失败，不能把软件校验当成独立灾备。

## 完整历史报告

API能力版本3提供`historyPagination`；`/api/reports?paged=1`按服务器保存的全部报告搜索与分页。
支持姓名、账号、报告编号、专业组合关键词，学生类型、年级、跟进状态、日期及排序。
分页独立于测评过程记录，返回页数、总量及当前筛选统计，最大页大小200；CSV直接从服务端导出全部匹配记录。
用户快速改动条件时取消旧请求并忽略迟到响应。API能力不足时保留旧版200条加载行为，并明确范围。

## 报告固定

新报告在生成时保存用于阅读的结构化正文；服务端按同版本规则重建并保存，重复提交保留首次结果。
学生端、后台预览与PDF读取已保存正文，后续修改推荐解释规则不会改写这份报告的特征、专业比较与建议。
正文不含后台备注或原始题目记录；登记姓名、报告编号及日期由对应报告元数据提供。
恢复旧报告时不重新评分。升级迁移对没有正文副本的历史报告按升级当时的规则保存一次，并标记`legacy-at-upgrade`；不能声称复原了历史版本原文。
已有正文副本保留，迁移命令默认预演，`--apply`才写入，写入前完整备份。

## 发布与回滚

先上传服务端V24包至阿里云，解压后运行`bash /root/majornavi-v24/upgrade.sh`。
更新器检查包校验值与JavaScript语法，核对现有PM2应用路径，停止且只更新`majornavi-report-api`。
保留整套原目录及数据备份，沿用现有PM2环境及自定义数据路径，不重新生成管理员密码；其他PM2应用不操作。
代码安装或健康检查失败时尝试恢复旧代码再启动，数据不自动回退到旧版本，避免覆盖更新期间合法记录。
服务器确认能力3后，再发布匹配前端。此包不包含.env、密码、真实账号或报告数据。
