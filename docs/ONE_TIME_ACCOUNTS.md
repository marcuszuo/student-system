# 一次性账号（V13，待服务端部署）

## 使用规则

- 管理员在后台登记使用者姓名或内部编号、年级、备注；随机账号以 mn 开头、密码16字符。
- 单次生成1—100个账号，1—365天有效期（默认30天）。批量账号可先填写班级，后续逐个编辑使用者信息。
- 明文密码仅在创建或重置响应中显示，支持复制与下载本批次CSV；服务端只保留随机盐的scrypt哈希。
- 登录后可以续答，刷新验证服务端会话后恢复本机草稿。账号重置增加使用代次，旧草稿不进入新一次测评。
- 报告写入成功才核销；以同编号重试返回原报告。相同账号同时提交不同报告只接受一份。
- 报告与核销状态在同一个访问账本原子写入，然后兼容写入原报告列表。中途写入失败不会产生“已核销但无报告”的状态。
- 完成后7天内可凭原账号登录查看/打印原报告，不能创建新报告。未完成时不能跨设备自动续答（草稿仍在原浏览器）；完成的报告可从服务器恢复。
- 停用立即拦截登录与会话；重置撤销旧会话、生成新密码、开放新一次测评并给予新的30天有效期。原报告保留。
- 账号表可直接查看关联报告；报告列表与详情显示登记使用者与账号，支持按使用者搜索。
- 管理登录12小时有效，仅保存在当前浏览器标签会话；服务端存储令牌哈希。学生会话30天，另受账号停用、重置、到期及完成后7天限制。

## 服务端范围

本次服务端实现用于 backend/node-report-api，已核对现网 /healthz 为Node接口。Cloudflare Worker版本不具备此账号功能，不能只发布静态前端。访问账本默认 DATA_DIR/access-store.json，权限0600。保持单个Node进程（PM2 fork模式，instances=1），不能让多个进程并行写同一文件；多实例时应先迁移到事务数据库。

启动时配置 ADMIN_LOGIN_PASSWORD 或 ADMIN_PASSWORD_HASH，即启用安全登录并拒绝旧的 x-admin-token 常量以及仅凭公开 ingest key 的学生报告写入。旧后台数据文件不需要迁移。正式报告、试测数据和反馈均绑定认证账号，学生只能取回本账号的原报告。gaokao查询保留原逻辑。

## 阿里云部署顺序

1. 在阿里云 ECS 控制台通过已有的“远程连接/Workbench”进入现有API服务器。无需在聊天中发送服务器密码。
2. 找到正在运行的 Node API 目录与进程：`pm2 list`，`pm2 describe <现有进程名>`。确认脚本目录和 DATA_DIR，先备份原服务代码及数据。不要新建空数据目录覆盖现有数据。
3. 将部署包中的 server.js、access.js、create-admin-login.js、package.json 上传到该API目录；不覆盖原 .env 与 data/。
4. 在API目录运行 `node create-admin-login.js /root/majornavi-private`。读取该私有目录中的 admin-first-login.txt，妥善保存新管理员密码。此目录和两个文件不得放到静态站点或Git仓库。
5. 加载现有环境及新管理员配置后，重启单实例API：

```sh
# 在现有 API 目录中执行；沿用原来的进程名和环境配置。
set -a
. ./.env
. /root/majornavi-private/admin-login.env
set +a
pm2 restart <现有进程名> --update-env
```

如果原服务由systemd或其他工具管理，应在对应服务中加入同样的管理员环境变量，并通过原管理方式重启。

6. 确认 `https://api.majornavi.cn/api/auth/capabilities` 返回 accounts:true，然后再发布V13静态前端。新前端不含固定管理员密码或管理令牌。
7. 用新管理员密码登录管理后台，生成一个专门的验收账号，验证登记→登录→报告→核销→查看原报告。不要直接使用真实学生账号做破坏性验证。

更新前端前，应确认新的服务端已就绪。服务端启用安全登录到前端发布之间安排短维护窗口，避免旧前端使用公开凭据提交失败。
